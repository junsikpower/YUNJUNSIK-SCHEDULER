# 💕 윤준식 스케줄러 — Text-to-Action (TTA)

**"쓰던 습관 그대로, 관리는 알아서."**

워드프로세서에 쓰던 그대로 줄글로 하루 계획을 쓰면, 앱이 문장 속 시간을 읽어 폰과 컴퓨터 양쪽에 알림을 울리고, 함께 남긴 메모는 따로 모아 보관합니다.

Flutter · Windows / Android / iOS · 완성 2026-04-12 · [English README →](README.md)

---

## 1. 왜 만들었나

저는 매일 아침 **워드프로세서**에 하루 계획을 썼습니다. 입력 칸도, 일정 추가 창도 없이 그냥 한 페이지의 글이었습니다. 이렇게 쓰는 건 빠르고 자연스러웠습니다.

문제는 **쓴 다음**이었습니다. 그 문서는 하루 종일 폴더 안에 닫힌 채 있었고, 10시 25분쯤엔 10시 30분 수업이 있다는 사실 자체를 잊어버렸습니다. 계획은 좋았지만 하루 동안 그 계획을 인식하지 못했습니다. **말을 걸지 않는 계획은 실행되지 않습니다.**

일반 캘린더 앱으로 옮겨봤지만 정착하지 못했습니다. 구조화된 캘린더에 입력하는 건 계획을 *쓰는 것과는 다른 행위*라 느리고 생각의 흐름을 끊기 때문입니다. 그래서 목표를 의도적으로 좁게 잡았습니다.

> **계획을 쓰는 방식은 아무것도 바꾸지 않는다. 쓰고 난 다음을 전부 바꾼다.**

어느 기기에서든 쓰던 습관은 그대로 두고, '기억하는 일'만 앱이 대신 맡습니다. 계획을 짜며 끄적인 메모도 함께 수집합니다.

---

## 2. 무엇을 하는가

- **줄글을 씁니다.** 하나의 일반 텍스트 에디터. 늘 쓰던 폰트와 간격 그대로, 입력 양식 없음.
- **문장 속에서 시계를 읽습니다.** `09시`, `9:30`, `10시 30분~13시`, `오후 3시`, `23시~01시`. 시간이 없는 줄은 바로 위 일정에 붙습니다.
- **자정 넘김을 압니다.** `23시 30분~01시 30분`은 종료 알람을 *내일* 새벽 1시 30분에 겁니다. 새 날짜 제목을 만들 필요가 없습니다.
- **두 기기에서 울립니다.** 모든 시작·종료 시간이 실제 OS 알림이 됩니다. 모바일은 시스템 알림, 윈도우는 토스트 알림.
- **하루 시작 전에 브리핑합니다.** 첫 일정 30분 전, 두 기기 모두에 오늘 계획과 메모가 담긴 **데일리 다이제스트**가 옵니다. 사실 이 알림 하나가 원래 문제의 진짜 해답입니다.
- **끄적인 메모를 모읍니다.** 백틱 세 개로 감싼 내용은 **메모 보드**에 날짜별로 정리됩니다.
- **한쪽에서 쓰면 양쪽에서 울립니다.** 노트북에서 저장하면 몇 초 뒤 폰이 알아서 자기 알람을 다시 겁니다. 오프라인에서도 동작합니다.
- **윈도우에선 숨어 있습니다.** 창을 닫아도 종료되지 않고 트레이로 숨어 알람을 계속 보냅니다.

**화면 3개:** 계획 에디터(작성 + 실시간 미리보기) · 메모 보드 · 알림 센터(오늘 알람 목록과 on/off).

## 3. 전체 흐름

앱 전체가 하나의 파이프라인입니다. **텍스트 입력 → 구조 추출 → 알람 + 메모.**

```
✍️  자유 줄글 (폰 또는 PC)
     │
     ├──────────────► ☁️  클라우드 (날짜별로 한 칸씩) ──실시간 스트림──► 🖥️  다른 기기 ──┐
     │                                                                                    │
     ▼                                                                                    │
   파서  ◄─────────────────────────────────────────────────────────────────────────────┘
     │
     ├──► 실시간 미리보기
     ├──► 메모 보드
     └──► 알람 예약기 ──┬──► 📱 모바일 알림
                         └──► 🖥️  윈도우 토스트
```

실제 일은 세 개의 엔진 파일이 처리하며, UI와 분리되어 있습니다.

| 파일 | 역할 |
|---|---|
| [`schedule_parser.dart`](lib/engine/schedule_parser.dart) | 텍스트 → 구조화된 하루 계획. 순수 로직, 의존성 없음. |
| [`notification_service.dart`](lib/engine/notification_service.dart) | 하루 계획 → 각 플랫폼의 OS 알람. |
| [`firestore_service.dart`](lib/engine/firestore_service.dart) | 텍스트 ↔ 클라우드 + 오프라인 캐시. |

## 4. 각 기능은 어떻게 구현했나

### 🕐 시간 파서 — `schedule_parser.dart`

하나의 정규식이 사람이 실제로 쓰는 모든 형식을 받아들입니다(오전/오후 표시, 시, `시` 또는 `:`, 선택적 분, 선택적 범위 기호). 사용자에게 엄격한 문법을 강요하지 않기 위해서입니다. → [`#L51`](lib/engine/schedule_parser.dart#L51)

문서를 한 줄씩 훑으며 각 줄을 세 가지로 분류합니다. → [`#L68`](lib/engine/schedule_parser.dart#L68)

- **날짜 줄**(숫자 + 년/월/일) — 직전 날짜 섹션을 마감하고 새 섹션을 엽니다. → [`#L196`](lib/engine/schedule_parser.dart#L196)
- **시간 줄** — 일정 블록이 되며, `~` 를 기준으로 시작과 종료를 나눕니다. → [`#L132`](lib/engine/schedule_parser.dart#L132)
- **그 외 모든 줄** — 바로 위 블록에 이어 붙습니다. 여러 줄짜리 상세 설명이 올바른 시간대에 묶이는 이유입니다.

정규화 단계에서 `24시`는 `00시`로, `오후 3시`는 `15시`로 바꾸고, 0~23을 벗어난 값은 오탐으로 버립니다. → [`#L168`](lib/engine/schedule_parser.dart#L168)

### 🌙 오버나이트 감지

시작이 22시 이후이고 종료가 06시 이전이면 자정을 넘긴 것이 명백합니다. 이때 종료 시각을 내부적으로 **24+ 공간**으로 밀어(01:00 → "25:00") 이후의 모든 정렬 로직에서 *시작 < 종료* 가 유지되게 합니다. → [`#L145`](lib/engine/schedule_parser.dart#L145)

실제 시각이 필요한 순간에만 24를 다시 빼고 달력 날짜를 하루 넘깁니다. → [`#L273`](lib/engine/schedule_parser.dart#L273)

한 문서에 날짜 섹션이 여러 개일 수 있으므로 "지금이 어느 날인가"도 정해야 합니다. 자정 기준으로 넘기면 하루가 새벽 1시 30분에 끝나는 사람에겐 무의미하므로, **다음 섹션의 첫 일정 30분 전**에 전환합니다. 데일리 다이제스트가 울리는 순간과 같습니다. 브리핑을 받는 순간부터 새 하루가 시작됩니다. → [`#L206`](lib/engine/schedule_parser.dart#L206)

### 📝 메모 인식

메모는 백틱 세 개로 표시합니다. 치기 쉽고 한국어 일정문에서 우연히 입력될 일이 없는 기호입니다.

문서 전체를 이 기호로 분할한 뒤, **조각 인덱스의 홀짝만으로** 정체를 판별합니다. 짝수는 일정 텍스트, 홀수는 메모. 한 번의 순회, 상태 머신 불필요, 중첩 버그 없음. 중요한 건 시간 스캐너가 홀수 조각을 아예 보지 않는다는 점입니다. 덕분에 "3시에 만나기로 함" 같은 메모가 유령 알람을 만들 수 없습니다. 메모는 현재 열려 있는 날짜 섹션에 붙으므로 날짜별 그룹화가 자동으로 됩니다. → [`#L76`](lib/engine/schedule_parser.dart#L76)

이 결과를 두 곳이 소비합니다. 키 입력마다 다시 그려지며 메모를 노란 박스로, 날짜 줄을 굵은 핑크로 보여주는 **실시간 미리보기**([`tta_text_painter.dart`](lib/widgets/tta_text_painter.dart)), 그리고 메모가 있는 날짜 섹션만 골라 보여주는 **메모 보드**([`memo_board_screen.dart`](lib/screens/memo_board_screen.dart))입니다.

### 🔔 알림 예약 구조

예약은 **완전 선언형**입니다. 기존 알람을 부분 수정하지 않고, 텍스트가 바뀔 때마다 전부 지우고 처음부터 다시 만듭니다. 그래야 "지금 어떤 알람이 존재하는가"가 "텍스트가 무엇을 말하는가"의 순수 함수가 됩니다. → [`#L239`](lib/engine/notification_service.dart#L239)

재구성 순서는 이렇습니다. **전체 취소** → 활성 날짜 섹션 선택 → 자유 텍스트 제목에서 실제 달력 날짜 확정 → 가장 이른 시작을 찾아 그 **30분 전에 데일리 다이제스트** 예약 → 시작 시간마다, 종료 시간마다 알람 하나씩 예약(이미 지난 것은 건너뜀).

id는 단순 순차 번호로 부여합니다. 알림 센터가 *같은* 알고리즘으로 같은 순서를 재구성하므로, 화면의 스위치가 실제 취소할 알람과 정확히 대응합니다. → [`alarm_center_screen.dart`](lib/screens/alarm_center_screen.dart)

다이제스트 본문은 계획 전체와 메모 섹션을 합쳐 만들고, OS 알림 길이 제한에 맞춰 잘라냅니다. → [`#L399`](lib/engine/notification_service.dart#L399)

요청·성공·실패·대기 건수와 최근 로그를 관찰 가능한 상태로 발행하는 진단 채널도 있습니다. "알람이 안 울렸다"는 남의 폰에서는 달리 디버깅할 방법이 없기 때문입니다. → [`#L14`](lib/engine/notification_service.dart#L14)

### ⏰ 알람이 실제로 울리는 방법

모든 알람은 **서로 독립적인 두 레이어에 이중 등록**됩니다. 어느 한쪽만으로는 모든 상황을 감당할 수 없기 때문입니다.

| 레이어 | 울리는 상황 |
|---|---|
| **OS 스케줄러** | 앱이 백그라운드거나 종료됐거나 기기가 절전 중일 때 |
| **인프로세스 타이머** | 앱이 켜져 있을 때 — 그리고 윈도우에서는 *유일한* 경로 |

예약은 단순 로컬 시각이 아니라 **타임존이 명시된 시각**으로 합니다. 그래야 시간대나 서머타임 변경이 모든 알람을 조용히 어긋나게 만들지 않습니다. → [`#L118`](lib/engine/notification_service.dart#L118)

**모바일에서는** 최신 안드로이드가 배터리 절약을 위해 정확한 알람을 적극적으로 제한합니다. 그래서 **권한 상태에 따른 단계적 폴백 사다리**를 뒀습니다. 허용되면 정확 예약, 아니면 부정확 예약, 실패하면 재시도 — 침묵하는 대신 성능만 낮춰 계속 동작합니다. 알림 권한과 정확한 알람 권한은 초기화 때 요청하고 *첫 프레임 이후에 다시 한 번* 요청합니다. 콜드 스타트 중에 권한 팝업이 삼켜지는 일이 잦기 때문입니다. 부팅 리시버를 등록해 재부팅 후에도 알람이 되살아납니다. → [`#L424`](lib/engine/notification_service.dart#L424) · [`AndroidManifest.xml`](android/app/src/main/AndroidManifest.xml)

**윈도우에서는** OS 스케줄러가 관여하지 않으므로 타이머 레이어가 곧 알람이고, 따라서 프로세스가 살아 있어야 합니다. 셸 설계가 그래서 이렇습니다. ✕ 버튼은 종료가 아니라 창을 **숨기고**, 트레이 아이콘이 *열기* / *완전히 종료* 를 제공합니다. 트레이의 종료만 실제로 앱을 끝냅니다. → [`main.dart#L88`](lib/main.dart#L88)

### ☁️ 폰 ↔ 컴퓨터 연동

의도적인 결정 하나가 설계 전체를 떠받칩니다. **원문 텍스트만 동기화하고, 알람은 절대 동기화하지 않는다.**

각 기기가 텍스트를 내려받아 로컬에서 파서를 돌려 *자기 알람*을 겁니다. 서버 측 스케줄링도, 푸시 토큰 저장소도, 팬아웃 인프라도 필요 없습니다. 그리고 우아하게 열화됩니다. 오프라인인 기기는 마지막으로 계산해둔 알람을 그대로 유지하니까요.

저장은 **날짜마다 한 칸씩** 나뉘어 있고, 그 안에 텍스트와 마지막 저장 시각이 담깁니다. 저장 시 로컬에도 미러링하는데, 네트워크 쓰기가 실패해도 **로컬 쓰기는 반드시 수행**합니다. 저장 실패가 곧 데이터 유실이 되지 않게 하려는 것이고, UI는 이를 조용히 넘기지 않고 정직하게 알립니다. 실행 시엔 클라우드를 먼저 시도하고 실패하면 로컬 캐시로 폴백한 뒤 즉시 다시 파싱해 알람을 겁니다. → [`firestore_service.dart`](lib/engine/firestore_service.dart)

두 기기를 한 앱처럼 느끼게 하는 건 실시간 루프입니다. 모든 기기가 오늘 날짜 칸을 실시간으로 지켜보고 있습니다. 노트북에서 수정 → 폰의 리스너 발화 → 폰이 다시 파싱 → 폰이 자기 알람을 지우고 다시 예약. 폰에서는 아무 조작 없이 몇 초 안에 일어납니다. 메모 보드와 알림 센터도 같은 스트림을 구독하므로 모든 기기의 모든 화면이 하나의 진실 원본을 읽습니다. → [`home_screen.dart#L69`](lib/screens/home_screen.dart#L69)
